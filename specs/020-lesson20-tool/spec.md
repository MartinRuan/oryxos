# Feature Specification: Tool 体系与 Plugin Tool 扩展机制

**Feature Branch**: `020-lesson20-tool`

**Created**: 2026-09-05

**Status**: Draft

**Input**: User description: "第20节需求：Tool 体系——让 Agent 具备与外部世界交互的操作能力（双手）。背景与价值：大模型本身只会生成文字，无法直接读取磁盘文件、运行系统命令或发起网络请求。为让 Agent 真正干活，需提供操作外部世界的工具。由 LLM 决定调哪个工具及传什么参数，系统负责真正执行并将结果递回给 LLM，完成 ReAct 循环中的 Act 动作。内置工具覆盖基础操作，业务方可通过 Plugin Tool 扩展业务能力。用户场景：1. Agent 需要读写本地文件或浏览目录；2. Agent 需要发起 HTTP 请求查询外部 API；3. 业务方通过声明外部 MCP 服务暴露工具给 Agent，单服务失联不影响系统；4. Agent 仅可调用当前 Profile 授权的工具子集。明确不做：Tool Policy 复杂规则链、超大量工具动态按需加载与分页、自身反向暴露为 MCP Server、容器/虚拟机级重隔离沙箱、单轮响应多工具并行调度。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 统一工具抽象与内置基础工具执行 (Priority: P1)

作为智能 Agent，我需要一组标准的外部交互工具（文件读取、写入、列目录，命令执行，HTTP 请求发起），以便在推理过程中调用它们读取本地环境信息、操作文件或拉取网络数据，且所有操作均受到前置安全拦截保护。

**Why this priority**: 工具抽象是 Agent 具备外部世界交互能力的绝对核心基石。没有内置工具，Agent 只能停留在文字思考阶段，无法完成任何具体现实任务。

**Independent Test**: 可以通过独立调用文件工具（如读取指定测试文件）、命令工具（执行 echo）、HTTP 工具（请求本地/Mock 接口）进行验证，确保执行结果返回且异常时正常拦截。

**Acceptance Scenarios**:

1. **Given** 统一工具注册表，**When** 遍历每个工具实例，**Then** 工具名称、功能描述和输入参数规范三件套均完整存在且非空。
2. **Given** 合法的文件路径与有效内容，**When** 调用文件写入和读取工具，**Then** 文件被安全写入并在读取时返回与写入一致的内容。
3. **Given** 合法的系统命令与参数，**When** 调用命令执行工具，**Then** 进程执行并正确返回标准输出内容；若命令超时则终止并报告错误。
4. **Given** 合法的 HTTP GET/POST 请求地址与载荷，**When** 调用 HTTP 工具，**Then** 成功获得响应状态码与响应体内容。
5. **Given** 未经授权的非法路径、非白名单命令或未授权域名，**When** 尝试执行对应工具，**Then** 在执行前被前置安全拦截器阻断并抛出违规异常，不得执行底层操作。

---

### User Story 2 - 工具注册表管理与 Profile 权限过滤 (Priority: P2)

作为企业系统管理员与 Agent 运行时，我需要一个集中的工具注册中心，能汇总管理所有已注册的工具；并且当特定 Agent 运行时初始化时，系统能根据该 Agent Profile 中声明的 `tools` 列表，精准过滤并仅暴露已授权的工具子集，杜绝越权工具调用。

**Why this priority**: 企业场景下不同业务 Agent 的权限必须隔离（例如只读 Agent 不能拥有写文件或执行 Shell 权限），精确过滤是保证 Agent 权限边界的关键。

**Independent Test**: 在注册表中注册多种工具，使用包含特定工具名称列表的 Profile 进行过滤，断言返回的工具集合名称与 Profile 声明完全一致（不多不少）。

**Acceptance Scenarios**:

1. **Given** 注册表中包含文件、命令、网络以及外部协议等多种来源的工具，**When** 查询所有工具列表，**Then** 能够完整返回所有已注册工具。
2. **Given** 某个 Agent Profile 仅声明了 `[read_file, http_get]` 两个工具，**When** 为该 Profile 筛选可用工具集合，**Then** 返回集合恰好只包含这两个工具，未声明的工具均被隔离排除。
3. **Given** 某个 Agent Profile 声明了不存在的工具名，**When** 执行过滤，**Then** 仅返回实际存在且匹配的工具，并有清晰的警告提示或忽略处理。

---

### User Story 3 - 外部 MCP 协议工具适配与容错隔离 (Priority: P3)

作为业务集成人员，我希望能够通过配置文件声明外部 MCP Server（Model Context Protocol 服务），系统启动时自动建立连接、动态获取该 Server 暴露的工具列表并转化为统一工具对象注册到系统中；当某个外部 MCP Server 网络断开或不可用时，系统具备故障隔离韧性，不会导致整机启动崩溃，其余正常工具仍可使用。

**Why this priority**: 外部 MCP 协议是业务方零代码/轻代码复用外部生态（如 GitHub MCP、Database MCP）的标准通道，外部依赖的不稳定不能影响底座核心系统可用性。

**Independent Test**: Mock 两个外部 MCP 服务的客户端（一个正常响应工具列表，另一个抛出连接拒绝异常），触发连接流程，断言正常服务的工具被正确注册，异常服务的故障被隔离记录且启动正常完成。

**Acceptance Scenarios**:

1. **Given** 配置了有效的 MCP 服务定义，**When** 系统建立连接并查询工具列表，**Then** 服务端暴露的每个工具被封装为标准工具对象并注册进注册表，其参数契约与原服务定义一致。
2. **Given** 已注册的 MCP 工具，**When** 运行时调用该工具的执行方法，**Then** 请求参数原样转发至目标 MCP 服务，返回内容正确封装为执行结果；若调用失败则标记为可重试或不可重试错误。
3. **Given** 配置中的某个 MCP 服务处于宕机或连接超时状态，**When** 系统尝试连接所有 MCP 服务，**Then** 记录 WARN 警告日志并安全跳过，系统启动过程不中断，其他健康服务的工具仍正常注册。

---

### Edge Cases

- 当工具输入 JSON 格式非法或缺少必填字段时，工具执行器应返回失败结果并给出清晰的参数错误说明，而不应崩溃抛出未捕获异常。
- 当 Shell 工具执行耗时超过预设最大超时时间时，底层进程应被强制销毁并返回超时错误。
- 当外部 MCP Server 返回的工具列表为空，或工具名称与内置工具发生冲突时，应具备明确的命名冲突处理策略（如日志告警或带前缀区分）。
- 当 Agent Profile 中 `tools` 列表为空时，该 Agent 应只能进行纯文本思考，无法调用任何外部工具。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供统一的工具抽象契约，约定名称 (`name`)、功能描述 (`description`)、参数结构定义 (`inputSchema`) 及执行方法 (`execute`)，使得推理引擎调用时对工具的具体技术实现和来源无感知。
- **FR-002**: 工具执行返回结果必须结构化包含成功标识 (`success`)、输出内容 (`content`)、错误信息 (`errorMessage`) 以及失败是否可重试标识 (`retryable`)。
- **FR-003**: 系统必须提供内置文件工具集，包含读取文件 (`read_file`)、写入文件 (`write_file`) 和列出目录 (`list_dir`)。
- **FR-004**: 系统必须提供内置命令执行工具 (`shell`)，支持直接传递命令与参数数组，具备超时中断保护。
- **FR-005**: 系统必须提供内置 HTTP 请求工具，包含 GET 请求 (`http_get`) 与 POST 请求 (`http_post`)。
- **FR-006**: 所有内置涉外 IO 工具（文件、Shell、HTTP）在执行实际物理操作的第一行，必须调用安全检查机制进行白名单与路径穿越校验，校验不通过时直接阻断。
- **FR-007**: 系统必须提供集中式工具注册中心 (`ToolRegistry`)，支持动态注册工具、按名称查找工具及获取全局所有工具。
- **FR-008**: 工具注册中心必须支持根据 Agent Profile 中的 `tools` 名称列表过滤生成该 Agent 专用的工具子集，且过滤结果必须精确匹配声明列表。
- **FR-009**: 系统必须提供 MCP 协议客户端管理服务 (`McpClientService`)，能够从配置文件（`.oryxos/mcp_servers.yaml`）加载外部服务配置，并在启动时尝试连接各个服务获取工具列表。
- **FR-010**: 系统必须提供 MCP 工具适配器 (`McpToolAdapter`)，将 MCP 远端工具定义无缝包装为统一工具契约，并负责执行调用转发与结果转换。
- **FR-011**: MCP 客户端连接与工具拉取必须具备容错隔离机制，任意单个外部 MCP 服务的网络故障或异常不得阻断系统启动，且不得影响其他工具的正常注册。
- **FR-012**: 前序第 19 节交付的出站通知工具 (`notify`) 必须以统一工具标准注册到工具注册表中，与其他内置工具共享相同的调用契约与生命周期。

### Key Entities *(include if feature involves data)*

- **OryxTool**: 统一工具抽象，定义工具的元数据契约（名称、描述、参数结构）与执行入口。
- **ToolResult**: 工具执行结果载体，封装执行状态、返回内容、错误提示及可重试标记。
- **ToolRegistry**: 全局工具注册中心容器，维护工具名称到工具对象的映射，支持集合过滤。
- **McpServerConfig**: 外部 MCP 服务配置实体，包含服务名、传输类型（stdio/sse）、启动命令及环境变量等。
- **McpToolAdapter**: MCP 工具适配器实体，持有 MCP Client 连接与远端工具规范，实现统一工具契约。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 注册表中 100% 的已注册工具满足契约完整性：名称、描述、入参结构全部非空。
- **SC-002**: 根据 Profile `tools` 列表过滤工具时，准确率为 100%（不多一个未授权工具，不少一个已授权有效工具）。
- **SC-003**: 模拟外部依赖失联测试时，100% 的失联异常被降级隔离为日志告警，系统启动失败率为 0%。
- **SC-004**: 内置工具集（文件、命令、网络）的基线功能自动化单测通过率达到 100%，越界访问拦截率达到 100%。

## Assumptions

- 核心阶段针对内置文件工具、命令工具和网络工具的安全检查，优先复用或对齐第 19 节已建立的 `Sandbox` 门面接口契约，全面实现将在第 23/24 节完成。
- MCP 协议集成在单测环境下采用模拟 Client，不强依赖本地操作系统已安装外部 Node.js/Python MCP 运行时。
- 单轮对话中的多个工具调用由 ReAct 循环按顺序串行调度，暂不进行多工具并行异步并发执行。
