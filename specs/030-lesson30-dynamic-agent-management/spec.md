## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通过接口动态管理 Agent (Priority: P1)

业务系统或运营人员可以创建一个 Agent、查看其定义、更新运行配置或任务正文，并在不重启服务的情况下删除它。成功创建或更新后，Agent 立即可调用，声明的定时任务同步生效；删除后不再可调用或触发，但定义文件仍可追溯。

**Why this priority**: 这是管理能力的主闭环，也是其他录入方式与页面操作共同依赖的基础。

**Independent Test**: 创建一个带定时声明的最小 Agent，确认它立即出现在列表中且可调用；更新定时声明后确认只有新任务生效；删除后确认运行时不可见且定义进入归档。

**Acceptance Scenarios**:

1. **Given** 一个合法且名称未占用的 Agent 定义，**When** 用户提交创建，**Then** Agent 立即出现在列表和详情中、可以调用，并注册其定时任务。
2. **Given** 一个已存在的 Agent，**When** 用户更新正文、Provider 或通知引用，**Then** 下一次调用读取新定义且无需重启。
3. **Given** 一个已存在且有定时任务的 Agent，**When** 用户更新其定时声明，**Then** 旧定时任务先停止，之后只保留新定时任务。
4. **Given** 一个已存在的 Agent，**When** 用户删除它，**Then** 系统先停止其定时任务，再移出运行时索引，最后归档整个 Agent 目录。
5. **Given** 创建或注册在中途失败，**When** 操作结束，**Then** 系统回滚已写入的 Agent 目录，不留下半注册状态。

---

### User Story 2 - 手工投放目录即时生效 (Priority: P2)

运维人员可以通过复制、版本同步或编辑器直接新增、修改、移走 Agent 目录，系统在运行期间自动识别变化，并使运行时状态与工作区保持一致。

**Why this priority**: 文件系统是 Agent 的唯一真相源，手工投放必须与接口创建具有相同结果，才能保证可运维性和行为一致性。

**Independent Test**: 在服务运行时手工放入一个合法 Agent 目录，确认无需重启即可查询和调用；修改后确认新定义生效；移走后确认运行时和定时任务被注销。

**Acceptance Scenarios**:

1. **Given** 服务正在运行，**When** 运维人员放入一个合法 Agent 目录，**Then** 系统在 5 秒内完成注册且无需重启。
2. **Given** 一个已注册 Agent 的目录，**When** 运维人员修改其定义，**Then** 系统重新校验并更新运行时状态与定时任务。
3. **Given** 一个已注册 Agent 的目录，**When** 运维人员移走该目录，**Then** 系统注销其定时任务并从运行时索引移除。
4. **Given** 工作区中出现一个非法 Agent 目录，**When** 系统处理该变化，**Then** 记录可诊断信息并继续监听其他目录。

---

### User Story 3 - 一句话生成 Agent 草稿 (Priority: P3)

运营人员可以输入一句自然语言目标，获得一份完整的 Agent 定义草稿，在预览区检查和修改任务正文、工具权限与定时设置，确认后再正式创建。

**Why this priority**: 它降低了定义 Agent 的门槛，同时通过预览确认保留人在环中的控制。

**Independent Test**: 输入一句业务目标，确认返回的草稿可被现有 Agent 定义规则解析，并验证生成步骤本身没有写目录、注册 Agent 或注册定时任务。

**Acceptance Scenarios**:

1. **Given** 一句清晰的 Agent 目标，**When** 用户请求生成草稿，**Then** 系统返回一份可解析的完整 Agent 定义且不落盘、不注册。
2. **Given** 生成内容缺少必填信息或格式非法，**When** 系统校验草稿，**Then** 返回可读的参数错误且不产生运行时状态。
3. **Given** 一份生成草稿，**When** 用户修改敏感字段并确认创建，**Then** 系统按正式创建流程处理修改后的内容。
4. **Given** 一次草稿生成请求，**When** 外部模型调用成功或失败，**Then** 系统均保留对应的模型调用审计记录。

---

### User Story 4 - 在管理平台管理和浏览工作区 (Priority: P4)

运营人员可以在管理平台完成 Agent 的生成、预览、创建、查看、编辑和删除，也可以展开工作区目录树并只读查看 Agent 与归档目录中的文本文件。

**Why this priority**: 页面把已有接口组合成可直接操作的工作流，并让目录真相源可见。

**Independent Test**: 仅通过浏览器完成“一句话生成 → 修改预览 → 创建 → 查看详情 → 编辑 → 浏览目录文件 → 删除”的完整流程，并确认错误信息可见、删除前需要二次确认。

**Acceptance Scenarios**:

1. **Given** 用户打开 Agent 管理页，**When** 数据加载完成，**Then** 页面列出所有 Agent 并提供查看、编辑和删除操作。
2. **Given** 用户输入一句目标，**When** 草稿生成完成，**Then** 页面展示可编辑预览，只有用户确认后才正式创建。
3. **Given** 用户打开工作区页，**When** 展开 Agent 或归档目录并选择文本文件，**Then** 页面只读展示文件内容。
4. **Given** 用户尝试删除 Agent，**When** 尚未二次确认，**Then** 系统不发送删除请求。
5. **Given** 任一管理请求失败，**When** 页面收到错误响应，**Then** 页面展示服务端返回的可读错误信息。
6. **Given** 用户进入 Agent 详情，**When** 点击记忆 Tab，**Then** 页面只展示该 Agent 的专属记忆与兼容的历史共享记忆。
7. **Given** 用户进入 OS运行时，**When** 展开子菜单，**Then** 只提供 Provider、Tool 与 Sandbox 白名单，不再提供会话和长期记忆入口。

### Edge Cases

- 同名 Agent 已由接口创建、手工目录或启动扫描注册时，新的创建请求必须在写目录前拒绝。
- Agent 目录正在被分步写入且暂时缺少完整定义时，单次处理失败不得终止持续监听；后续文件变化可再次触发校验。
- 接口写目录同时触发文件监听时，不得留下重复定时任务或不一致的运行时注册。
- 更新失败时，原 Agent 定义和原运行时状态必须仍可继续使用，不能只更新其中一侧。
- 删除或归档目标不存在时，应返回不存在错误且不得影响其他 Agent。
- 同名归档目录已存在时，归档结果仍须唯一、完整且可追溯。
- 工作区文件路径为空、指向目录、指向二进制文件、包含目录穿越或符号链接越界时，必须拒绝读取并给出可读错误。
- 一句话生成发生超时、供应商不可用或返回非 Agent 定义文本时，不得落盘或注册。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将每个 Agent 的专属目录作为其定义与运行配置的唯一真相源。
- **FR-002**: 系统 MUST 支持创建、列出、查看、更新和删除 Agent，并保持既有一次性调用能力不变。
- **FR-003**: 正式创建 MUST 接受结构化 Agent 字段或一份完整 Agent 定义文本，最终只写入目标 Agent 目录中的主定义文件。
- **FR-004**: 创建 MUST 在成功返回前完成定义校验、目录写入、运行时注册和定时任务注册。
- **FR-005**: 创建过程中任一步失败 MUST 回滚该操作已写入的目录和运行时状态。
- **FR-006**: 系统 MUST 在写入任何文件前拒绝已存在的 Agent 名称及非法目录名称。
- **FR-007**: 查询结果 MUST 提供 Agent 名称、描述、正文、Provider、模型、工具、通知引用和定时声明等安全定义信息，不返回密钥值。
- **FR-008**: 更新 MUST 允许只提交需要变化的字段，且不得通过更新改变 Agent 名称。
- **FR-009**: 更新正文、Provider 或通知引用成功后 MUST 在下一次调用时生效，无需重启。
- **FR-010**: 更新定时声明 MUST 先注销旧定时任务，再注册新定时任务，并确保失败时不产生新旧任务并存。
- **FR-011**: 删除 MUST 按“注销定时任务、移出运行时索引、归档整个 Agent 目录”的顺序执行，不物理删除 Agent 定义。
- **FR-012**: 系统 MUST 在启动时扫描现有 Agent，并在运行期间持续识别 Agent 目录的新增、修改和移走。
- **FR-013**: 接口写入、手工目录变化和启动扫描 MUST 汇入同一注册行为，使用相同校验、运行时注册和定时注册规则。
- **FR-014**: 单个非法目录或单次监听处理失败 MUST 被记录，并且不得停止对其他 Agent 目录的持续监听。
- **FR-015**: 系统 MUST 支持根据一句自然语言目标生成可预览的 Agent 定义草稿。
- **FR-016**: 草稿生成 MUST 只返回结果，不得写文件、注册 Agent 或注册定时任务。
- **FR-017**: 生成草稿 MUST 经现有 Agent 定义规则校验；非法生成结果返回可读的参数错误。
- **FR-018**: 每次草稿生成的外部模型调用无论成功或失败 MUST 进入既有模型调用审计。
- **FR-019**: 系统 MUST 允许运维人员独立配置草稿生成所用的 Provider 和模型，缺省使用 `minimax` 与 `MiniMax-M2.7`。
- **FR-020**: 系统 MUST 提供 Agent 与归档目录的只读目录树，并允许读取其边界内的文本文件。
- **FR-021**: 工作区文件读取 MUST 拒绝规范化后位于工作区根目录之外的路径，并防止通过符号链接越界。
- **FR-022**: 所有管理操作的成功和错误 MUST 使用项目既有的统一响应格式及既有 HTTP 状态码口径。
- **FR-023**: 管理平台 MUST 提供 Agent 管理页，覆盖列表、生成草稿、可编辑预览、创建、查看、编辑、二次确认删除和错误反馈。
- **FR-024**: 管理平台 MUST 提供只读工作区页，支持展开 Agent/归档目录并查看文本文件内容。
- **FR-025**: 本功能 MUST 保持模型调用、工具执行、会话身份和定时执行的既有审计与安全边界不变。
- **FR-026**: 新写入的长期记忆 MUST 使用当前 `ProfileContext` 中的 Agent 名称建立关联，且不得改变 `save_memory`/`recall_memory` Tool 的输入结构。
- **FR-027**: Agent 的核心记忆注入、归档检索和管理页面查询 MUST 只包含该 Agent 的专属条目与未标记的历史共享条目，不得包含其他 Agent 的专属条目。
- **FR-028**: 未携带 Agent 名称的既有长期记忆查询与无 Profile 上下文的读写调用 MUST 保持兼容。
- **FR-029**: Agent 详情 MUST 提供记忆 Tab；OS运行时 MUST 移除会话和长期记忆子菜单及对应内容区。

### Key Entities

- **Agent Definition**: 一个 Agent 的完整声明，包含唯一名称、描述、任务正文、Provider/模型、可用工具、通知引用和定时声明，存放在其专属目录中。
- **Agent Runtime Registration**: Agent 定义在当前进程中的可用状态及其定时任务句柄，与 Agent 目录保持一致。
- **Generated Draft**: 根据自然语言目标生成并完成格式校验的 Agent 定义文本；在用户确认创建前没有持久化或运行时状态。
- **Archived Agent**: 已从运行时注销并从活动目录移入归档区的完整 Agent 目录，保留历史定义用于追溯。
- **Workspace Node**: 工作区目录树中的目录或文件节点，包含安全的相对路径、名称、类型及可展开的子节点。
- **Agent Memory Entry**: 保存在共享 `MEMORY.md` 中、通过 `[agent:<name>]` 标记归属的长期记忆条目；无标记历史条目视为共享记忆。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 合法 Agent 创建成功后，100% 在响应返回时即可查询和调用，无需重启服务。
- **SC-002**: 手工新增、修改或移走 Agent 目录后，95% 的变化在 5 秒内反映到运行时状态。
- **SC-003**: 对创建、更新和删除进行故障注入时，100% 不留下半写目录、重复定时任务或失去原定义的中间状态。
- **SC-004**: 100% 的一句话生成请求在用户确认前不产生文件、运行时注册或定时任务。
- **SC-005**: 100% 的有效生成结果可被现有 Agent 定义规则解析，所有无效结果均返回可读错误。
- **SC-006**: 100% 的目录穿越和符号链接越界读取尝试被拒绝，工作区根目录内的正常文本文件可读取。
- **SC-007**: 用户可以在 3 分钟内仅通过管理平台完成“生成、预览、创建、查看、编辑、浏览、删除”流程。
- **SC-008**: 新增功能上线后，既有 Agent 调用、定时任务、会话及审计回归测试保持全部通过。
- **SC-009**: 两个 Agent 写入同一关键词的专属记忆后，各自的 Prompt、检索和详情页均 100% 不出现另一 Agent 的专属内容，同时都可读取历史共享条目。

## Assumptions

- 草稿生成 Provider 可由运维配置覆盖；未配置时使用 `minimax` 与 `MiniMax-M2.7`。
- 本阶段部署在受信任内网，认证鉴权随未来 API Key/RBAC 能力补充。
- JSON 创建只写主定义文件；带脚本或子指令的复杂 Agent 通过手工投放目录，multipart/zip 上传不在本节范围。
- 工作区浏览器只读，不提供在线文件编辑。
- 不增加 Agent 启用/停用状态、创建时 dry-run、Agent 版本历史或生成过程的多轮追问。
- Provider、Tool、通知渠道与定时任务的既有校验和审计能力可复用，不新增数据库表。
- Agent 名称遵循现有目录名称约束；更新请求中的名称由路径确定且不可修改。
- 归档目录冲突通过唯一归档名称解决，同时保留原 Agent 名称与归档时间用于追溯。
