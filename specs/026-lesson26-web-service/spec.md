# Feature Specification: Lesson 26 - Web Service and Read-Only Admin Console

**Feature Branch**: `026-lesson26-web-service`

**Created**: 2026-09-12

**Status**: Draft

**Input**: 为业务系统提供完整的 OryxOS 对外服务门面：支持连续会话与一次性 Agent 调用，提供 Profile、Memory、Tool 和系统状态查询；所有入口共享既有 Agent 引擎和持久化能力，使用统一响应与错误语义，并提供只读管理页面。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 业务系统进行连续 Agent 对话 (Priority: P1)

作为接入 OryxOS 的业务系统，我希望创建会话、在同一会话中连续发送消息、查询最近的对话历史，并在结束后归档会话，以便将 Agent 能力嵌入需要上下文连续性的业务流程。

**Why this priority**: 连续会话是 Web Service 的核心价值，也是证明 Web 与 CLI 复用同一执行引擎和持久化能力的主路径。

**Independent Test**: 创建一个会话，连续发送两条消息后查询该会话，确认响应来自既有 Agent 引擎、历史按顺序保存且最多返回最近 100 条；归档后确认该会话不再接受新消息。

**Acceptance Scenarios**:

1. **Given** 一个有效的 Profile，**When** 业务系统创建会话，**Then** 系统返回可用于后续消息和查询的会话标识。
2. **Given** 一个活动会话，**When** 业务系统发送非空且不超过 32KB 的消息，**Then** 系统只调用一次统一 Agent 处理入口，并返回 Agent 回复。
3. **Given** 一个已有多轮消息的会话，**When** 业务系统查询会话，**Then** 系统返回该会话最近最多 100 条消息及当前状态。
4. **Given** 一个活动会话，**When** 业务系统归档会话，**Then** 系统标记其为已归档且拒绝继续处理该会话的新消息。

---

### User Story 2 - 业务系统一次性调用 Agent (Priority: P1)

作为只需要单次结果的业务系统，我希望按 Agent 名称提交一次请求并同步获得结果，无需自行管理会话生命周期。

**Why this priority**: 一次性调用是业务系统最常用的集成方式，与连续会话共同构成对外服务的最小可用能力。

**Independent Test**: 使用已注册 Agent 发起单次调用，确认系统使用临时会话复用统一 Agent 引擎并返回结果；再分别模拟 Agent 不存在、Provider 不可用和处理超时，验证错误语义。

**Acceptance Scenarios**:

1. **Given** 一个已注册 Agent，**When** 业务系统提交有效输入，**Then** 系统通过统一 Agent 处理入口执行并同步返回结果。
2. **Given** 一个不存在的 Agent 名称，**When** 业务系统发起调用，**Then** 系统返回资源不存在错误。
3. **Given** Provider 不可用，**When** Agent 调用失败，**Then** 系统返回服务暂不可用错误。
4. **Given** Agent 调用超过 60 秒，**When** 等待期限到达，**Then** 系统终止本次等待并返回超时错误。

---

### User Story 3 - 查询 OryxOS 能力与运行状态 (Priority: P2)

作为运维人员或接入方，我希望查询已注册 Profile、可用 Tool、长期记忆内容、服务健康状态和运行信息，以便了解当前实例能做什么以及是否可以接收请求。

**Why this priority**: 可发现性和状态查询降低集成与排障成本，但不阻塞核心 Agent 调用路径。

**Independent Test**: 在不连接真实模型的环境中分别查询五类信息，确认均通过真实应用装配链路返回统一格式的结果，且 Provider 状态能够被识别。

**Acceptance Scenarios**:

1. **Given** 系统已加载若干 Profile 和 Tool，**When** 接入方查询能力列表，**Then** 返回当前已注册内容的只读描述。
2. **Given** 工作区存在长期记忆，**When** 接入方查询记忆，**Then** 返回当前可读取的完整长期记忆内容且不提供写入操作。
3. **Given** 服务正在运行，**When** 接入方查询健康与运行信息，**Then** 返回服务状态及各 Provider 的连通状态。

---

### User Story 4 - 使用只读管理平台观察实例 (Priority: P3)

作为系统管理员，我希望在浏览器中通过一个无需额外安装的管理页面查看会话、Profile、Tool、长期记忆和运行状态，以便快速检查实例，而不会误改运行配置或业务数据。

**Why this priority**: 管理页面提升可用性，并验证公开查询能力足以支撑外部客户端；核心调用能力不依赖该页面。

**Independent Test**: 打开管理页面，逐一访问五个导航区域，确认页面显示真实数据、统一展示服务错误，且不存在新建、编辑、删除或执行类控件。

**Acceptance Scenarios**:

1. **Given** 服务已启动，**When** 管理员访问管理入口，**Then** 页面直接加载并显示会话列表、Profile、Tool、长期记忆和运行状态五个导航项。
2. **Given** 任一查询成功，**When** 管理员切换到对应导航项，**Then** 页面展示该查询返回的真实内容。
3. **Given** 任一查询失败，**When** 页面收到统一错误响应，**Then** 页面向管理员显示其中的用户可读消息。
4. **Given** 管理员浏览任一页面，**When** 检查可用操作，**Then** 页面不提供创建、编辑、删除 Agent 或写入 Memory 的入口。

### Edge Cases

- 消息为空、仅含空白或超过 32KB 时，系统拒绝请求且不调用 Agent 引擎。
- 会话或 Agent 不存在、会话已归档时，系统返回明确的资源或状态错误。
- Provider 故障和 60 秒处理超时使用可区分的错误语义。
- 未预期内部异常只写入内部日志，对外响应不得包含数据库地址、路径、堆栈或原始异常消息。
- 会话历史超过 100 条时，只返回最近 100 条并保持原始顺序。
- Profile、Tool 或 Memory 为空时，查询返回有效的空结果，而不是内部错误。
- 管理页面收到网络失败或非成功响应时，保留导航能力并显示可读错误。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供创建会话、列出会话、向指定会话发送消息、查询指定会话和归档指定会话五项会话能力。
- **FR-002**: 系统 MUST 将 Web 消息交给与 CLI 相同的 Agent 处理入口，并保证每个有效请求只触发一次处理。
- **FR-003**: 系统 MUST 拒绝空消息和超过 32KB 的单条消息，并返回参数错误。
- **FR-004**: 系统 MUST 在查询会话时最多返回最近 100 条消息。
- **FR-005**: 系统 MUST 支持按 Agent 名称进行一次性同步调用，并由系统管理此次调用所需的临时会话。
- **FR-006**: 系统 MUST 为 Profile、Tool、长期记忆、健康状态和运行信息提供只读查询能力；运行信息 MUST 包含 Provider 连通状态。
- **FR-007**: 所有成功与失败结果 MUST 使用同一响应结构，包含业务码、用户可读消息、数据和时间戳。
- **FR-008**: 系统 MUST 将参数错误、资源不存在、内部错误、Provider 故障和调用超时分别映射为 400、404、500、503 和 504 语义。
- **FR-009**: 未预期内部错误的外部响应 MUST 使用固定通用消息，不得泄露原始异常内容；详细信息仅进入内部日志。
- **FR-010**: Agent 调用 MUST 以 60 秒为最长等待时间，超过期限时返回超时结果。
- **FR-011**: 核心阶段 MUST 允许浏览器调试客户端跨来源读取公开服务。
- **FR-012**: 系统 MUST 自动提供覆盖全部核心服务操作的可浏览接口说明。
- **FR-013**: 系统 MUST 提供无需独立部署和构建步骤的只读管理页面，包含会话、Profile、Tool、长期记忆和运行状态五个区域。
- **FR-014**: 管理页面 MUST 仅调用本特性公开的查询能力，不得提供 Agent 创建或修改、Memory 写入、权限管理、调度管理或其他写操作入口。
- **FR-015**: 管理页面的会话区域 MUST 调用会话集合查询并展示真实会话列表；本特性核心服务操作总数为 11 个。
- **FR-016**: 系统 MUST 保持同步请求响应行为，不引入流式结果或长连接交互。

### Key Entities

- **Session**: 一段连续 Agent 对话，具有唯一标识、Profile、渠道、用户、消息历史、状态和活动时间。
- **Agent Invocation**: 一次按 Agent 名称触发的独立请求，包含输入、临时会话上下文、结果或错误状态。
- **Capability Summary**: 对当前 Profile、Tool、Memory 和 Provider 状态的只读描述。
- **Service Response**: 对外统一结果，包含业务码、消息、数据和时间戳。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 接入方可以仅通过公开服务完成创建会话、列出会话、连续发送消息、查询最近历史和归档会话的完整流程，五项能力成功率为 100%。
- **SC-002**: 在验收样例中，每个有效消息请求恰好触发一次既有 Agent 处理流程，Web 与 CLI 产生的会话均可从同一存储中查询。
- **SC-003**: 32KB 消息边界、100 条历史边界以及 60 秒等待边界均可通过自动化测试精确验证。
- **SC-004**: 参数错误、资源不存在、内部错误、Provider 故障和调用超时五类失败均返回一致的四字段结构和各自约定语义。
- **SC-005**: 任何内部异常验收样例的外部响应中均不出现原始异常消息、数据库连接串或本地路径。
- **SC-006**: 在不连接真实模型的验收环境中，健康、运行信息、Profile 和 Tool 四条真实应用链路全部可达。
- **SC-007**: 200 个并发一次性调用可以由单实例接收处理，且不因请求执行模型产生线程耗尽或响应格式错误。
- **SC-008**: 管理页面五个区域均能渲染真实查询结果，其中会话区域展示集合查询返回的会话列表，且页面中写操作入口数量为 0。

## Assumptions

- 核心阶段部署在可信内网，不提供认证、API Key、JWT、RBAC 或限流。
- SSE、WebSocket、Webhook、Agent 目录管理、Memory 写入、调度管理及审计统计界面属于后续范围。
- 既有 Agent 引擎、Profile 注册、Tool 注册、Memory、Session 持久化和审计能力均可直接复用，不在本特性中改变其公开契约。
- 默认服务端口为 8080；消息请求使用同步方式获得完整结果。
- 统一响应沿用第 24 节已有的成功与错误公共信封，不新建第二套错误响应模型。
